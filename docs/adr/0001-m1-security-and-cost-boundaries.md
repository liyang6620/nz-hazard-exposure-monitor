# ADR 0001: M1 security and cost boundaries

## Status

Accepted for plan review, 2026-10-23.

## Context

M1 must deploy one low-cost Function App, protect it with a durable budget stop,
and permit GitHub to plan and deploy without a stored Azure credential. Public
network endpoints are necessary to stay within the USD 3 monthly ceiling.

## Decision

- Use one Linux Flex Consumption FC1 plan with Python 3.12, 2 GB memory, one
  maximum instance, and no always-ready instances.
- Use public Azure endpoints with TLS, Entra authorization, RBAC, and disabled
  storage anonymous access. Private endpoints are excluded because their fixed
  costs conflict with C1.
- Give the Function a system-assigned identity for runtime access. A separate
  user-assigned identity is limited to the deployment package container because
  Flex requires the package identity before the Function's system identity
  exists.
- Keep the Function public over HTTPS because Function access restrictions
  apply to the whole app and would block the browser approval routes. Protect
  `budget_stop` with a 32-byte random token generated by Terraform. The token is
  stored only in protected remote state, the Function setting and the Action
  Group webhook URI. Approval GET/POST use expiring, one-time HMAC tokens.
- Use separate Action Groups. Function exceptions send email only; budget
  exhaustion sends email and invokes `budget_stop`. Reusing one group would stop
  production for an ordinary application failure.
- Give the Function a custom role containing only `Microsoft.Web/sites/read`
  and `Microsoft.Web/sites/stop/action`, assigned at the one Function App.
- GitHub uses one user-assigned managed identity with repository-scoped PR and
  `main` OIDC federated credentials. It has state-container data access plus
  `Contributor` and `Role Based Access Control Administrator` only on the
  production resource group. It has no subscription role. Repository
  environment gates control when plan and deployment workflows can use it. Its
  RBAC Administrator assignment has an ABAC condition: only the five runtime
  roles plus the custom stop role may be assigned or removed, and only for
  `ServicePrincipal` principals. Bootstrap owns the custom role definition.
- Azure OpenAI local-key authentication is disabled. The deployment is
  `gpt-5-mini` Global Standard with capacity 1 and runtime limits of minimal
  reasoning, 1,200 maximum output tokens, 12,000 total reserved tokens per
  briefing, and 10 briefings per month.

## Consequences

The public endpoints increase exposure compared with private networking, so
route-level authentication, the webhook token and least-privilege RBAC are
mandatory. All HTTP decorators use anonymous platform auth so browser and
Action Group calls do not require Function keys; those keys are not accepted as
application authorization and do not bypass route checks. Global Standard may
process prompts and responses in any Azure region, including outside Australia.
This is accepted because the model receives only public earthquake and exposure
data. There are two
no-charge Action Groups because a shared webhook group would create an unsafe
failure mode. The first deployment needs an owner-run bootstrap before OIDC can
take over CI planning and code deployment. If managed-identity federation or
scoped role assignment is rejected, deployment falls back to owner-run
`az login`; CI then runs only formatting and validation.
